# 知识点正文写作规范

本规范用于逐点更新 `data/catalog.json` 中的教材内容。所有知识点必须保持同一体例，使整套教材读起来连续。

## 一、结构

每个知识点由三部分组成：

| 数据键 | 内容 |
|---|---|
| `lessonLibrary[<id>]` | 讲解页：`lead`、可选 `history`、`sections[]`、`references[]` |
| `lessonNotes[<id>]` | `worked`（一个具体例子）与 `pitfall`（一个常见误解） |
| `exerciseBank[<id>].questions[]` | 书写题，仅 `prompt`、可选 `notation`、`answerText`、可选 `answerTable` |

## 二、正文块

`sections[]` 的每一项必须有一个 `title`，并可包含下列任意组合：

| 字段 | 渲染结果 | 使用场合 |
|---|---|---|
| `body` | 段落 | 正文叙述 |
| `points` | 列表 | 并列要点、步骤 |
| `def` | 定义框 `{label, text}` | 引入术语，编号如「定义 1.1（偶数）」 |
| `table` | 表格 `{caption, head, rows}` | 记号表、对照表 |
| `formula` | 公式条 | 单个核心公式 |
| `proof` | 证明块 `{label, text, qed}` | 定理与证明；`text` 用 `\n` 分行 |
| `example` + `exampleLabel` | 编号例题 | 具体演算或反例 |

## 三、硬性要求

1. **先解释符号，再使用符号。** 本节首次出现的任何记号（如 `¬`、`∧`、`∀`、`∈`、`∅`），都必须先在同节的记号表中给出「记号 / 读法 / 含义」，之后才可进入公式。
2. **不要使用尚未在课程中出现的前置记号。** 若本知识点在课程顺序中靠前，只使用当前及更早知识点已引入的符号。
3. **定义、定理、例题都要编号**，如「定义 2.1」「定理 2.2」「例 2.1」，编号在本知识点内连续。
4. **证明必须分步**：每一步都说明依据（定义、已证结论、运算性质或某条规则）。
5. **只要有步骤，就必须换行**：例题、证明、练习答案中的多步推导，每步单独一行；跨多行的演算优先用「步骤 / 等式 / 依据」表格。不要把多个步骤挤进一段连续文字。
5. **正文用陈述句**，不使用「你会发现」「让我们」「先认符号」等口语讲解腔；不使用第二人称。
6. **每个知识点至少包含**：一个引入动机的段落、一个定义框、至少一个例题、一个易错点。
7. **练习只有书写题**：给出题目与参考答案，不设选项、不设提示、不设自评清单。答案要能直接对照，长度与教材解答相当。若答案需要表格（如真值表），把表格放进 `answerTable`（结构同 `table`），不要把行列挤进一段文字。
8. **历史信息放在 `history`**，只作为动机说明，不作为先修条件；引用需可核查。
9. 不写空话。每个段落都应对应一个具体概念、步骤或例子。

## 四、篇幅

- `sections`：8–13 节。
- `lead`：2–4 句，说明本节解决什么问题。
- 每个 `body`：2–5 句；需要展开时用 `points`。
- `exercises`：4 题，覆盖概念辨析、计算/推导、反例或错误分析、应用。
